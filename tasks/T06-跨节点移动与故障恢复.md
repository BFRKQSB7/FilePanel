# T06 — 跨节点移动与故障恢复

## GOAL

在网页安全移动文件到其他存储节点，传输中断或重启后可恢复，原分享路径保持不变。

## USER VALUE

管理员能利用另一台机器的磁盘，迁移失败不会丢失唯一完整文件。

## WHY NOW

T05已提供真实节点与传输原语；把唯一副本切换隔离为高风险任务，避免节点接入任务同时承担破坏性恢复逻辑。

## CONTEXT

一个文件平时只有一个活动主位置；本任务不建立可调度副本池。移动期间源继续提供下载，目标先作为临时对象，完整传输并核验大小/SHA-256后才切换元数据；切换成功后清理旧源，清理失败不等于迁移失败。主机与节点之间可直传时直传，不可直达则显式面板中转，所有路径均受每跳预算和磁盘预留约束。稳定文件ID、版本与分享slug不变，节点IP不是对象身份。用户看见预检、传输、校验、切换、清理及失败/重试。既有读租约、离线策略和授权不能绕过，面板失联期间不自行执行不确定的源删除。

## CONTRACT

1. 任务阶段持久化：预检/预留→传输→校验→主位置切换→源清理→完成，所有外部写操作用稳定任务ID幂等。
2. 源保持可用直到目标完整校验和数据库主位置切换提交；源清理只能作用于该任务已证明非活动主位置的确切对象/版本，禁止按文件名删。
3. 同文件同时移动/删除必须串行化或用版本CAS；任务重试需持久fencing版本，过期worker不能提交位置或删除源。
4. 切换与任务阶段同事务提交；切换前崩溃保持源，切换后崩溃按已提交主位置恢复，不能把清理失败又回滚成唯一源。
5. 活动读者持有源读租约时延迟清理，最迟读租约结束后重试；重启或失联不能伪造读租约已释放。
6. 空间预算包含在途目标临时文件，所有节点/中转用量检查；校验失败不删除源、不公开临时目标。
7. 取消语义由阶段决定：切换前可取消并清理已证实临时目标，切换后只继续安全清理，不把完成切换伪装成取消。
8. 任务重启对账只清理已证实可删对象；不确定的元数据/身份冲突保持文件、报告需处理，不能盲目扫描删文件。
