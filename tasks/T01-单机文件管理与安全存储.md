## GOAL

从当前纯文档目录直接实现可启动、可登录、可安全管理私有文件的单机应用。

## USER VALUE

管理员无需外部数据库或额外节点即可在网页上传、下载、重命名、删除文件，重启后数据保留。

## WHY NOW

整个项目尚无代码，账号、持久化与文件生命周期是真实共同前置；把它们和可用后台一次完成，避免纯基础层交接。

## CONTEXT

FilePanel 面向个人 VPS/NAT 主机，一台机器必须独立可用。当前只有项目文档与参考 PNG，没有源码、schema、测试或安装脚本；本任务不需要重新读这些设计文档。采用 Go 主程序、SQLite、本地文件与嵌入静态资源，运行时不依赖 Node、Docker、MySQL、Redis；库版本在执行时查官方资料并锁定，不新建选型报告。后台一级导航固定“文件、数据、教程、设置”，只实现本任务功能，其余入口显示尚未提供，不能放无效按钮。单管理员通过随机一次性初始化令牌设置密码，上传永远默认私有。文件显示名与内部对象键分离，完整文件必须经过流式写入、大小/SHA-256 校验和一致性提交。未来分享、节点、传输与保护复用这些原语，但不为未来创建大量空模块。

## CONTRACT

1. 本机节点稳定存在，内部 ID 不取自 IP；仅本机可启动。建议一个 Go 二进制提供 `serve` 与后续 `node` 子命令，具体 CLI 可按最小实现选择。
2. 密码慢哈希、随机初始化令牌单次消费、会话失效、登录尝试限制与 CSRF 同时落地；日志不记录密码和令牌，匿名者不能读取管理文件信息或内容。
3. 文件名仅显示，内部随机键存于受控数据根；拒绝目录穿越、符号链接逃逸，正式文件不放公开静态根。
4. 上传状态必须区分接收、校验、可用与失败；临时文件不进入正式列表；未知长度请求也有空间上限，取消要释放预算。
5. 空间保护须适配 1GB 小盘，按测试环境文件的当前资源契约确定非零安全余量及受控配置，不再固定至少保留 1GiB；使用实际文件系统空闲量并扣除并发在途预留，持续检查，所有落盘入口复用该原语。
6. SQLite schema 从第一版起版本化；已发布迁移不可改写。元数据提交与文件落盘失败可重启对账，不得把缺失文件标成可用。
7. 删除先撤销可读状态再清理对象，失败可重试；下载中的对象以读租约或等价机制保护，不能让清理造成错误读取或删到别的文件。
8. 主服务不要求 root；开发配置可用独立临时目录运行，不擅自安装系统服务、初始化 Git 或修改用户其他项目。
