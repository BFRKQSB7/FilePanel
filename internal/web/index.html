    使用帮助

    从上传到分享，以及图片、存储和访问问题的操作指南。

    你想做什么？

    一台服务器就能上传和分享文件；域名、额外节点、副本与多条下载线路都按需配置。主面板安装后，通过实际可用的后台地址完成初始化或登录，即可开始使用。

    快速开始：上传并分享

    1. 进入“我的文件”，点击“上传文件”或将文件拖入上传区域。等待显示“已完成”；如果连接中断，先刷新列表确认文件是否已经保存，再决定是否重试。
    2. 在文件行点击“分享”，选择“私密分享”或“公开分享”。不填写标题、介绍和图片也可以分享；可选的下载页面模板只改变页面布局。
    3. 点击“保存分享设置”，等待保存成功，再点击“复制分享链接”。建议用未登录的浏览器或另一台设备打开链接，检查页面和下载是否正常。

    三种状态：不分享时仅管理员可访问；私密分享不在公开主页出现，但任何拥有链接的人都可以访问；公开分享既在主页展示，也可通过链接访问。私密链接不是密码保护，请只发给可信的人。

    文件与分享管理

    如何重新编辑、切换或取消分享？
    1. 在“我的文件”找到文件，再次点击“分享”，修改分享方式、模板、下载线路或介绍。
    2. 点击“保存分享设置”后，点击“查看分享页面”检查效果。文件重命名或更换存储位置后，分享链接保持不变。
    3. 取消分享可点击文件旁的“取消分享”，或在分享窗口选择“不分享”并保存。取消后原页面和下载授权失效，文件与图片保留；再次开启分享前，访客无法访问。
    如何批量管理分享？
    1. 在文件列表上方按分享状态筛选，也可以搜索文件名。
    2. 勾选要处理的文件，或使用“全选”；核对已选数量。
    3. 选择“批量转私密分享”“批量转公开分享”或“批量取消分享”，按提示确认。操作的是已选文件，请先核对选择范围。
    如何查找、选择、重命名和删除文件？

    搜索框可按名称查找，类型和分享状态可组合筛选；右上角可切换列表与网格。单击选择文件，双击查看属性，右键打开操作菜单；Ctrl 可多选、Shift 可连续选择，选中单个文件后按 F2 重命名。也可通过文件旁“更多”操作。

    删除文件不可从面板恢复：删除会使分享和介绍页失效，并清理关联图片与所有存储副本；离线副本会保留清理记录并等待处理。需要保留内容时，请先自行备份。

    分享页面与素材库

    如何在介绍里插入图片或更换封面？
    1. 在文件旁点击“分享”，展开“编辑介绍与图片（可选）”。在“文件介绍”里输入文字，并把光标放到希望显示图片的位置。
    2. 点击“上传图片”，或点击“从素材库选择”查看该文件已有的素材。图片上传成功后立即保存并占用空间，即使关闭窗口或没有保存分享设置也会保留。
    3. 在图片下点击“插入正文”，会在光标处插入图片标记；也可点击“设为封面”或勾选“展示为截图”。点击“预览”检查正文效果。
    4. 点击窗口底部“保存分享设置”，图片引用才会生效。之后可再次打开分享设置，移除旧图片标记或取消封面、截图，选择新图片并保存。

    正文支持普通文字和 Markdown，例如 # 标题、- 列表项、**加粗**；不支持 HTML。每个文件最多 8 张图片，每张不超过 2 MiB，支持 PNG、JPEG、GIF 和 WebP。

    素材库的分类和删除是什么意思？

    左侧“素材库”集中展示分享图片，可按图片名、所属文件和使用状态筛选。“使用中”表示已保存为封面、正文图片或截图；“未使用”表示没有已保存的引用。分享编辑窗口的“本次上传”只标记当前窗口上传的图片，不等于已经用于页面。

    关闭编辑窗口或取消分享不会自动删除图片；分享关闭后，已保存的引用仍算“使用中”。未使用的图片不向访客公开。素材属于各自文件，当前不能跨文件复用；删除所属文件时，其素材也会被清理。

    1. 要删除使用中的图片，先进入该文件的分享设置，移除它在封面、正文和截图中的所有引用，然后保存。
    2. 返回素材库，筛选“未使用”，勾选需要删除的图片，点击“删除所选未使用图片”并确认。删除是永久操作，不能恢复；使用中的图片有删除保护。

    多机存储与下载线路

    添加节点前：两个网址分别从哪里来？

    主面板地址是节点用来连接主面板的 HTTPS 地址，也是管理员和访客访问站点的入口。例如 https://files.example.com，填写到“节点连接的面板 HTTPS 地址”时不要加 /admin。节点机必须能访问它。

    节点地址是主面板访问额外服务器上节点服务的 HTTPS 地址，例如 https://node.example.com。生成接入命令后，在命令中的 JSON 把 endpoint 的占位地址换成节点的实际地址；JSON 中的 panel 是主面板地址，两者用途不同。

    通常给两台机器各用一个子域名，并分别解析到对应服务器的公网 IP；域名可来自同一个已购买的域名。例如主面板 files.example.com 指向主面板公网 IP，节点 node.example.com 指向节点公网 IP。这里的域名只是示例，不能直接照填。不同机器也可能共用一个公网 IP，这时须由服务商的端口映射或已有反向代理将各入口正确分流；不能只因为 IP 相同就填同一个入口。端口不是 443 时要写在网址里，例如 https://node.example.com:45001。

    公网 IP 和映射端口从各自服务器服务商控制台查询；域名从域名注册商购买或使用已有域名，在 DNS 托管平台添加解析。IP、域名、端口和证书要对应实际服务器，内网地址或服务器控制台显示的网卡地址不一定能从公网访问。

    如何实际接入一台节点？（Ubuntu 公网示例）

    下面以新装 Ubuntu、独立公网 IP、能使用 80 和 443 的节点机为例，使用 Caddy 提供节点 HTTPS。准备一台已经能用 HTTPS 访问的主面板、一台额外节点机、域名的 DNS 管理权限，以及节点机 SSH 登录信息。节点安装不会自动配置 DNS、防火墙或反向代理。示例域名必须换成你自己的；机器已有网站、代理或其他业务时，先确认端口和配置，不能覆盖现有服务。

    先选适用环境：独立公网 IP、Ubuntu 24.04、80／443 可达且无端口冲突，可按下面示例执行。已有 Nginx／Caddy 时复用原代理，先确认站点配置、证书、转发目标和重载方式；不要再安装另一个占用同端口的代理。NAT、共享 IP 或只有高位端口时，先向服务商确认公网 IP、外部端口→内部端口映射及外部 HTTPS 入口，不能照搬本示例的证书申请步骤。其他系统的包管理和服务命令不同；安装支持范围为 Alpine/OpenRC、Debian/systemd、Ubuntu 24.04/systemd，本例只给 Ubuntu 步骤。

    遇到不适用的情况，先整理系统版本、是否 NAT、节点公网 IP、外部→内部端口、已有代理和证书类型，再确定方案；不要公开 SSH 密码、证书私钥或接入命令。以下每阶段的检查未通过时，先排除问题再继续。

    1. 查询地址并设置解析。在节点服务器商控制台找到节点的公网 IPv4；在域名的 DNS 管理页面添加 A 记录：主机名填 node，记录值填节点公网 IPv4，例如得到 node.example.com。如果使用 Cloudflare，先选“仅 DNS”（灰云）进行直连测试。确认实际解析结果指向节点，且没有错误的 AAAA 记录。主面板和节点使用不同子域名，例如 files.example.com 和 node.example.com。
    2. 打开端口。在节点服务器商的安全组／防火墙放行 TCP 80、443；若系统防火墙启用，也需要放行。SSH 端口保持原样。节点程序的 8081 只监听本机，无需对公网开放。自动申请证书需要公网 80 和 443 能到达节点；NAT 没有这两个端口时，此示例不适用，请使用已有 HTTPS 代理或按实际映射另行配置。
    3. 登录节点机并检查占用。在自己的电脑打开终端，将下面的用户名、IP 和端口替换为节点服务商提供的 SSH 信息。登录后执行第二条命令：若 80 或 443 已被其他程序占用，不要继续照搬 Caddy 步骤。

    在自己的电脑执行（替换 SSH 信息）：

    ssh -p SSH端口 用户名@节点公网IP

    登录后在节点机执行：

    sudo ss -lntp

    检查结果：在自己的电脑或主面板机执行 nslookup node.example.com，将返回的地址与节点服务商提供的公网入口核对；Linux 没有 nslookup 时可用 getent hosts node.example.com 辅助检查系统解析。共享 IP 时同时核对映射端口。节点机的 ss 输出中查看 :80、:443 是否有 LISTEN，空闲才按本示例安装新代理。修改防火墙前保留 SSH 访问，不能仅凭本机监听判断公网可达。

    1. 在节点机安装并配置 Caddy。在 Ubuntu 终端运行 sudo apt update，再运行 sudo apt install caddy。使用 sudo nano /etc/caddy/Caddyfile 编辑配置；确认没有与现有配置冲突，再添加下面的站点块，把域名换成第 1 步的真实域名。不要删除其他站点配置。nano 中按 Ctrl+O、Enter 保存，Ctrl+X 退出。
    node.example.com {
    reverse_proxy 127.0.0.1:8081
}

    在节点机执行 sudo caddy validate --config /etc/caddy/Caddyfile，确认配置有效后执行 sudo systemctl reload caddy；如果服务未运行，先用 sudo systemctl start caddy。sudo systemctl status caddy 显示 active (running) 才继续。Caddy 会尝试为真实域名申请并续期证书；失败时检查 DNS、端口、时间和节点机日志 sudo journalctl -u caddy -n 50 --no-pager。不要关闭证书校验；修改现有配置前保存备份并确认可回退。

    1. 先检查节点 HTTPS。在主面板所在服务器上运行 curl -Iv https://node.example.com，替换为真实域名；确认 TLS 证书受信任且主机名匹配。节点尚未安装时返回 502 可以是代理已连接但后端未启动，不能据此认定节点已可用。此处超时、证书错误或访问到别的网站时先检查解析、端口和代理。
    2. 生成并修改命令。先在节点机执行 curl -Iv https://files.example.com/admin（替换成真实主面板地址），确认节点能连接且证书可信；失败先检查节点到主面板的 DNS、端口和 TLS。在主面板打开“设置 → 节点与线路 → 添加额外服务器（高级）”。“节点连接的面板 HTTPS 地址”填主面板的外网地址（例如 https://files.example.com，不带 /admin）；公网可信证书的 CA 留空。点击“生成一次性接入命令”，再点“复制接入命令”。
    3. 在节点终端执行。把命令先粘贴到本机文本编辑器，把 JSON 中 "endpoint": "https://节点域名:映射端口" 的值替换为节点实际地址，例如 "endpoint": "https://node.example.com"。不要改 panel、panel_id 和 ticket；公网可信证书的 node_ca 留空。复制修改后的全部多行命令到已登录节点机的终端执行。票据仅有效 5 分钟且只能使用一次，超时或用过就回面板重新生成；命令含凭据，不要公开。成功后命令会清理临时入网文件，失败时请保护该文件并在排错结束后删除。
    4. 检查并启用。安装显示成功后，在节点机执行 sudo systemctl status filepanel-node，确认 active (running)。回主面板点击“刷新节点”，找到新节点并点击“检查面板到节点”，确认控制连接在线且面板→节点的 TLS 与身份检查通过；未通过先查看卡片错误。按需求勾选“存储文件”或“提供下载线路”，点击“保存节点设置”。
    5. 实际验证。在“我的文件”的“上传存储位置”选择节点，上传一个小测试文件并等待“已完成”。开启分享后，用其他网络打开分享页并实际下载、比对文件内容；若要验证节点直出，还要在分享设置中指定该出口。只有控制连接在线不足以证明访客下载成功。

    字段核对：panel 是节点访问主面板的地址，ca 用于节点信任主面板的私有 CA；endpoint 是主面板访问节点的 HTTPS 地址，node_ca 用于主面板信任节点的私有 CA。公网可信证书对应的 CA 可留空；私有 CA 需要正确的 PEM 和匹配的证书名称。手动修改 JSON 中的 PEM 时，换行必须编码为 \n，不能直接把多行文本粘进 JSON 字符串；不要分享包含票据的文件。127.0.0.1:8081 是节点机内部监听，不是其他机器访问的地址。已有节点无需重复安装。

    Caddy 官方反向代理说明

    如何保存多个副本，或只保留一个位置？

    开始前：确认目标节点在线、有可用磁盘，并保留需要的数据备份。复制和移动会经过预检与校验，可能消耗各机器的磁盘和流量。

    1. 在文件旁选择“更多 → 存储与副本”，查看主位置和已校验副本。
    2. 在“新增副本位置”选择服务器，点击“复制并保留原件”。等待存储任务完成；新副本完成校验后才能使用。
    3. 要只保留一处，在其他非主位置点击“移除这个副本”，确认后查看清理任务。主位置始终保留；需要改变主位置时，在“更多”中选择“移动”。

    完成与排错：在文件页的“文件存储任务”查看“完成”和实际路径，再打开“存储与副本”核对位置。移动到已有副本的位置可复用已校验副本，无需重新传输；移除副本可能等待已有下载完成或离线节点恢复。失败时先查看任务错误、节点状态和空间，再使用页面提供的“重试 / 继续清理”；不要在服务器手动删除对象。

    存储位置和下载／中转出口有什么区别？

    存储位置决定文件副本放在哪台机器；下载出口决定访客从哪台机器接收数据。出口可以读取本机副本，也可以从存储服务器中转，因此只存一份也可配置其他可用出口，中转会消耗相关机器的流量。

    1. 先在“设置 → 节点与线路”配置并启用需要的出口，确认节点连接状态。
    2. 打开文件的“分享”，在“下载线路”选择使用所有已启用出口，或手动指定并勾选需要的服务器。
    3. 保存分享设置并打开分享页面，检查按实际出口地区显示的下载按钮；实际可用性仍需从访客网络测试。

    访问、用量与常见问题

    如何给主面板绑定域名，让访客从外网访问？

    适用：需要用域名访问已经安装好的主面板。准备域名 DNS 管理权限、主面板公网入口和当前可用的后台登录地址；仅有 NAT 高位端口或已有代理时，先确认映射和代理方案。此操作是可选的，单机上传与分享不要求绑定域名。

    1. 准备域名和公网入口。在域名注册商购买域名，或使用已有域名的一个子域名，例如 files.example.com。到主面板服务器服务商控制台查公网 IPv4 / IPv6、允许的外部端口及 NAT 映射；先保留目前能登录的入口。
    2. 添加 DNS 解析。在该域名的 DNS 托管平台新增 A 记录，把子域名指向主面板公网 IPv4；有可用公网 IPv6 时可另加 AAAA 记录。主机记录应按托管平台的填写规则输入，通常 files 对应 files.example.com。等待解析生效；没有公网 IPv6 时不要添加错误的 AAAA 记录。
    3. 选择 HTTPS 方式。自动申请证书需要该域名的公网 80 和 443 端口可达，且监听端口没有被其他服务占用；同时检查云安全组和系统防火墙。若已有 Nginx / Caddy 等代理，先在代理上配置域名、证书及转发到 FilePanel，再选择已有 HTTPS 代理。只有映射端口或 80 / 443 不可用时，不要假设自动证书可以成功，需使用已有可用代理或其他实际可达入口。
    4. 核对面板监听。安装实例默认自动 HTTPS 监听本机 127.0.0.1:8082（验证）和 127.0.0.1:8443（TLS），公网 80／443 需要实际转发到相应监听端口；安装时配置了低端口权限的实例可直接监听 80／443。打开“设置 → 访问地址”中的“详细运行环境”查看当前监听，按自己的安装和映射配置核对，避免占用现有服务。
    5. 在面板检查并启用。打开“设置 → 访问地址”，选择对应模式，在“完整访问地址”填入实际网址，例如 https://files.example.com；根据实际情况填写公网 IP、外部端口，以及是否使用 Cloudflare 等 DNS 代理。自动证书模式按页面提示填写邮箱并同意条款。
    6. 点击“检查候选地址”，查看下方诊断和 DNS／反代指导，处理失败或待验证项后重新检查；可用时点击“验证并启用”。等页面显示已启用，再用另一网络打开后台及分享链接测试。检查或启用失败时，原入口保留。

    完成标准：面板显示已启用，并在其他网络通过域名打开后台、分享页和实际下载。失败时检查下方“域名、端口或证书”排错，保留当前可用入口；检查结果为“待验证”不等于公网已通过。

    更换主域名可能改变以后生成的分享链接域名；要让旧域名继续可用，需要自行保留旧 DNS、证书和必要的跳转。使用代理时，证书由代理维护；FilePanel 不会替你修改现有代理或 DNS。

    如何修改密码、备份和更新？

    在“设置 → 账号安全”输入当前密码和新密码；修改后所有设备需要重新登录。忘记密码需要服务器管理员处理，不要删除数据目录重新初始化，也不要公开密码。

    更新前：查看“设置 → 更新与维护”的版本与检查结果；准备足够空间和可验证的一致性备份。面板备份包含本机文件、素材和数据库，但不包含远端节点上的正式文件；远端数据需要分别备份。外观配置包不是整站备份，节点迁移包也不包含本机文件、图片素材或 HTTPS 私钥。备份含敏感信息，限制权限并妥善保存迁移包密码。

    备份示例：在面板服务器终端执行以下命令，适用于实例名为 main 的已安装面板；其他实例须替换程序路径与实例名。先准备 root 控制、非数据目录内的备份父目录，目标子目录必须不存在，并确保有足够空间。完成后第二条命令检查备份；将验证通过的备份另存到安全位置，不能公开。

    sudo /opt/filepanel-main/filepanel maintain --instance main --action backup --backup-path /root/backups/site-before-update
sudo /opt/filepanel-main/filepanel backup verify --path /root/backups/site-before-update

    恢复与迁移：恢复会回到选定备份时的文件名、分享授权、账号和密钥状态，可能丢失之后的变更；先另存当前状态，确认实例身份、备份时点和兼容性，再由服务器管理员执行并验证下载。迁移节点身份前先导出加密迁移包并保存密码，切换时停止旧面板，不要同时运行相同身份的两台面板。更新或恢复可能短暂停止服务，失败时保留现场和备份，不要直接删除数据目录。

    确认需要恢复且已验证备份后，在面板服务器执行下例；路径需换成选定的备份目录，实例身份必须与备份匹配。该命令会切换数据，请不要用它仅仅测试命令是否可运行。

    sudo /opt/filepanel-main/filepanel maintain --instance main --action restore --backup-path /root/backups/site-before-update

    完成标准：更新后检查服务与版本，再确认登录、原有文件和实际下载；恢复后另核对分享状态、节点连接和远端文件。服务或文件异常时停止继续修改，先检查维护状态并使用已验证的备份恢复。

    常见术语：SHA-256、DNS、NAT 和 HTTPS

    SHA-256 是文件校验码，可用于比对下载是否完整；普通下载无需输入。DNS 将域名指向服务器地址；NAT 端口映射将外部端口转到服务器内部端口。HTTPS 加密浏览器与服务器之间的连接，证书用于验证服务器身份。公网地址和映射端口以服务商控制台的实际配置为准。

    排查常见问题

    从现象出发，逐层核对 DNS → 公网端口 → TLS → 代理 → 后端 → 实际下载。某一层失败时先处理该层；不要关闭证书校验或删除数据来试错。

    域名解析错误、只能本机访问或外部端口超时

    可能原因：DNS 指向错误 IP、内网监听、NAT 映射错误，或云安全组／系统防火墙拦截。

    检查：在电脑或另一台服务器执行 nslookup files.example.com，将 A／AAAA 结果与服务商提供的公网入口比较；代理开启时返回代理 IP，需同时核对 DNS 源站及代理设置。在对应服务器执行 sudo ss -lntp，检查服务监听地址与内部端口；到服务商控制台逐项核对公网端口→内部地址和端口的映射及安全组，再检查系统防火墙。127.0.0.1 只供本机访问，必须有实际代理或隧道入口。

    处理与复验：按实际情况修正 DNS、映射或放行规则，保留 SSH 和现有站点入口；等待 DNS 生效后从不同网络访问真实网址及端口。服务器本机监听正常不等于公网连通。Cloudflare 橙云异常时，先核对代理支持的端口、源站和证书；是否切换为仅 DNS 需结合已有服务影响判断。

    HTTPS 证书申请失败或域名不匹配

    可能原因：DNS 指向错误、HTTP-01 验证路径被挡、80／443 不通、代理证书配置或域名不匹配；仅凭一种报错不能确定根因。

    检查与复验：先按上一条核对 DNS 与端口。在访问方机器执行 curl -Iv https://files.example.com（换成实际域名和端口），查看 TLS 验证和证书名称，不能使用 -k 跳过验证。主面板自动 HTTPS 查看“设置 → 访问地址”的检查与证书状态；由 Caddy 或其他代理终止 TLS 时，到代理服务器查看证书和日志。修正后重新检查并从另一网络访问；未完成验证前保留旧入口。

    Caddy 配置错误、端口占用、启动失败或返回 502

    适用：Ubuntu/systemd 且节点入口使用 Caddy。端口冲突、配置语法错误、证书失败、上游未启动或地址写错均可能造成问题。

    在节点机检查：sudo ss -lntp 查看 80、443 和 8081 监听；sudo caddy validate --config /etc/caddy/Caddyfile 检查语法；sudo systemctl status caddy 和 sudo journalctl -u caddy -n 50 --no-pager 查看服务与日志。502 表示代理未能正常获得上游响应，常见原因是节点服务未启动或代理目标错误；节点安装前的 502 不能作为节点已接入的证明。

    处理与复验：确认现有服务归属后修正配置或上游，不要直接终止未知进程；验证配置后再重载。节点安装后检查 sudo systemctl status filepanel-node，从主面板所在机器再次访问节点 HTTPS，并在节点卡片执行“检查面板到节点”。证书申请／续期失败时查看日志并按上一条检查 DNS 和公网端口。

    节点离线、接入命令失败、服务未运行或面板无法连接

    可能原因：票据过期或已使用、命令字段错误、节点到面板的连接／信任失败、安装失败，或面板到节点的 HTTPS 路径不通。

    检查：在节点机确认命令完整、panel 指向主面板、endpoint 指向节点，私有 CA 与证书匹配；票据超过 5 分钟或已经使用则重新生成，不要公开命令。Ubuntu/systemd 上用 sudo systemctl status filepanel-node 和 sudo journalctl -u filepanel-node -n 50 --no-pager 查看服务；其他系统按实际服务管理方式检查。安装失败可能保留实例配置和数据，修正后按原配置重试，不要直接清空目录。

    复验：在节点机检查到面板的 HTTPS；在面板机检查到节点的 HTTPS、证书名和映射端口，再在“设置 → 节点与线路”刷新并点击“检查面板到节点”。卡片同时显示控制连接和面板→节点检查，两者都应核对。

    节点在线但访客无法下载，或副本／校验任务失败

    可能原因：源副本不可用、任务尚未完成、出口未启用或未允许、出口到存储不通、访客到出口不通，也可能是流量保护触发。

    检查与处理：确认分享没有取消，保存设置后重新复制链接；取消分享会使原页面和下载授权失效。在“我的文件”查看存储任务阶段、错误和“更多 → 存储与副本”；确认存在已校验可用副本，失败时检查节点在线、空间并按页面提示重试。检查分享设置中的下载线路、节点的“提供下载线路”及用量保护。控制连接在线不证明出口→存储或访客→出口畅通。

    复验：保存配置后从实际访客网络打开分享页面，逐一测试允许的下载按钮并核对下载文件；某条线路失败时查看该出口与源节点的连接及额度，不要删除唯一副本。

    流量保护触发，或统计与服务商账单不同

    可能原因：达到保护线、周期和计费口径不同，或服务商还计入其他应用及网络开销。磁盘容量用于存放文件，流量是传输的数据量；FilePanel 的应用内容流统计不等于整机网卡流量或服务商账单。

    检查与复验：在“用量与状态”查看保护状态及周期，在“设置 → 流量保护”核对真实套餐额度、仅发送／收发合计和 UTC 重置日；多机每跳分别计量，不能相加当作访客净下载量。达到保护线可等待下一周期或按真实套餐修正配置，保存后重新查看状态并实际下载；不要为了排错随意关闭保护。
