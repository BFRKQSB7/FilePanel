# 安装与本机卸载

面板与节点支持 Alpine/OpenRC、Debian/systemd、Ubuntu **24.04 LTS**/systemd，架构为 amd64/arm64。安装器核对 `/etc/os-release` 和运行中的 init，不会把仅安装了 systemctl 的空容器当成 systemd 环境。程序无 CGO 动态加载器依赖；无需 Docker、Bash、Node.js 或数据库服务。

## 准备可信的本地包

当前只提供本地/离线发布源，在线发布与网页更新归 T08。开发机在仓库根目录执行 `pwsh -File scripts/build-fixture.ps1`，得到 `dist/t07-fixture` 下两个 Linux 可执行文件与 `release.json`，脚本输出清单 SHA256。它们是测试 fixture，不是正式发布。

清单格式如下，`size` 是实际字节数，SHA256 是对应文件的小写十六进制摘要。生产使用时，**清单摘要必须来自独立可信的交付渠道**；从同一个陌生下载地址同时获取文件和摘要无法建立信任。

```json
{"version":"版本","artifacts":{"linux-amd64":{"file":"filepanel-linux-amd64","sha256":"64位摘要","size":15900000},"linux-arm64":{"file":"filepanel-linux-arm64","sha256":"64位摘要","size":15000000}}}
```

将适合目标架构的可执行文件、清单及 `scripts/install.sh` 放在 root 控制的目录，禁止放在其他用户可改写的目录。核对可执行文件摘要与清单摘要后安装，例如 amd64 面板：

```sh
# BINARY_SHA256 与 MANIFEST_SHA256 填入可信交付结果。
chmod 700 /root/filepanel-release/filepanel-linux-amd64
sudo sh ./scripts/install.sh /root/filepanel-release/filepanel-linux-amd64 "$BINARY_SHA256" \
  install --instance main --release /root/filepanel-release/release.json \
  --manifest-sha256 "$MANIFEST_SHA256" --listen 127.0.0.1:8080
sudo /opt/filepanel-main/filepanel maintain --instance main --action init-token
```

初始化令牌只在请求它的终端输出，不自动写入服务日志。访问候选入口 `/admin` 完成管理员初始化；默认只监听回环地址，管理员根据实际 NAT/反代条件开放访问，安装器不修改防火墙、DNS 或既有 Web 服务。

## 实例、权限和空间

实例名限 1–20 位小写字母、数字和短横线，必须以字母开头。每个实例使用独立的 `fp-实例名` 用户、`filepanel-实例名` 服务、root 控制的 `/etc/filepanel/实例名.json` 安装清单，以及 `/opt/filepanel-实例名/` 中的二进制、运行配置、日志、缓存和备份目录。业务数据默认位于 `/var/lib/filepanel-实例名/`。

自定义 `--data-dir /挂载盘/专用父目录/filepanel-实例名` 必须是**尚不存在的专用子目录**，父目录及祖先均由 root 拥有、不可被普通用户写入且无软链接。不能直接接管已有数据目录、共享目录或整盘。保留数据后重装需使用原实例名、原配置及原可信产物，安装器核对目录 inode、设备号、用户身份和文件摘要，拒绝静默覆盖数据库、密码或节点身份。

安装默认设置 `--reserve-bytes 16777216`，落盘仍保留磁盘总量的 5%，取两者较大值；可提高预留，不能低于 16MiB。所有已有业务写入共用 `files.Manager` 的预算、并发预留与持续检查。裸 `serve`/`node serve` 的默认预留仍为旧的 1GiB，完整默认策略与首版资源验收仍须在 T08 处理。安装空间预检覆盖二进制复制、数据库临时写入及非零安全余量。

默认面板自动 HTTPS 使用回环高位端口 8443/8082；需要直接绑定 443/80 时显式传入 `--low-ports`。systemd 仅开放 `CAP_NET_BIND_SERVICE`；OpenRC 路径需管理员预先准备 `setcap`（Alpine 的 libcap 工具），只对 root 拥有的本实例可执行文件赋予该能力，缺失工具时受控失败。节点安装使用回环 HTTP 与管理员已有 HTTPS 反代；也可在独立手动运行模式使用原有 `node serve --tls-cert/--tls-key` 接口。

## 节点接入

在面板设置页生成一次性接入命令，将其中 JSON 的节点 HTTPS 地址改为实际地址，私有节点证书填入 `node_ca`，并在节点终端设置已核验的 `FILEPANEL_MANIFEST_SHA256`。准备好本地 `filepanel` 和 `release.json` 后执行生成的命令；安装器通过 `--join-file` 读取私有 JSON，票据不出现在服务参数或公共日志中。命令使用 `umask 077` 创建该文件，入网后删除它。

新节点只有入网和服务健康检查都通过才报告安装成功。安装器自己复制的暂存入网文件自动删除；票据失败时保留实例清单和数据，修正私有输入后用原配置重试，或执行本机 purge。公开端点的端到端可达性仍在面板中检查，不能用回环端口可监听替代 NAT/HTTPS 验证。

## 维护与两种卸载

```sh
sudo /opt/filepanel-main/filepanel maintain --instance main --action status
sudo /opt/filepanel-main/filepanel maintain --instance main --action restart
sudo /opt/filepanel-main/filepanel uninstall --instance main
# 删除本实例数据与凭据：
sudo /opt/filepanel-main/filepanel uninstall --instance main --purge
```

维护动作只允许 `start`、`stop`、`restart`、`status`、`init-token`。启动和重启等待健康检查；服务以专用用户运行。没有 setuid、通用 root shell、sudoers 或 Web 提权入口；T08 可由管理员调用固定维护动作，再接入可信更新/备份协议。两类 init 都将服务加入自启，应用日志最多保留两个 1MiB 文件，不依赖全局 journald/logrotate 配置。

两种卸载均只确认一次，输入 `yes` 才执行。默认卸载删除本机服务和程序，保留数据、配置、身份、日志、备份和清单；之后用同一离线包重新安装。`--purge` 删除清单中属于本实例的目录和用户，清理前检查规范路径、所有权、目录身份、链接和挂载边界，遇到异常先拒绝，不删除共享父目录。

主面板卸载前按只读数据库列出节点地址/IP/备注、最后在线时间、关联文件数及记录大小，过期和不可读记录明确标注；这不是实时远端磁盘扫描。**所有卸载只影响本机实例，远端程序和文件保留**。面板卸载后分享入口不可用，节点拒绝新授权并在既有失联租约到期后停止活动传输；purge 后重装不会自动恢复管理关系。需要迁移时先使用已有加密节点迁移功能。

## 定向检查

`scripts/smoke-lifecycle.py --wsl Debian` 在开发机驱动真实服务测试；远端参数见脚本 `--help`，必须提供固定 SSH 主机密钥校验文件。`--keep` 仅供继续节点测试，使用后必须清理。Go 测试 `TestInstalledLifecycle` 通过 `FILEPANEL_INSTALLED_SMOKE=1` 显式启用，只管理 `t07-panel`、`t07-node` 和专用 fixture；默认测试跳过破坏性 smoke。测试机连接与资源契约以 [测试环境](../TEST_ENVIRONMENT.md) 为准，执行结果只在任务索引与当次回复记录。

服务参数依据 [systemd.exec](https://www.freedesktop.org/software/systemd/man/256/systemd.exec.html) 与 [OpenRC supervise-daemon 指南](https://github.com/OpenRC/openrc/blob/master/supervise-daemon-guide.md)，Ubuntu 范围依据 [24.04 LTS 发行说明](https://documentation.ubuntu.com/release-notes/24.04/)。
