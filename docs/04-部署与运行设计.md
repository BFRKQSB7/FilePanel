# 部署与运行设计

**状态：目标流程，尚无可执行安装器、服务单元或升级器。** 本文的程序名和目录是拟定约定，不能直接当作当前安装说明。

## 1. 支持目标与安装

首版只面向 Alpine Linux / OpenRC 与 Debian / systemd，CPU 架构拟支持 amd64 与 arm64；优先验证 Alpine 3.23 与 Debian 13，不扩展其他发行版。实际模板版本、架构与服务管理器按测试记录确认，不能从 Linux 构建通过推导双系统可用。资源目标与测试机信息以根目录 [测试环境与轻量验收](../TEST_ENVIRONMENT.md) 为准；爱尔兰套餐仅有 Alpine，Debian 使用另一个真实隔离环境验证。NAT、IPv6 与既有反代均需单独验收。

正式安装器应检测系统、架构、必要网络和端口，下载与平台匹配的校验发布物，创建专用运行用户与数据目录，注册服务并输出真实可达的访问候选地址。失败时显示已完成步骤与恢复方法，不能在下载或服务启动失败后仍输出安装成功。

首次初始化凭证随机且只能用于初始化，不写入公开日志或文档。建议使用一次性初始化令牌，首次设置管理员密码后失效；初始只有 HTTP 时界面说明当前连接状态，并提供通过安全访问路径初始化的指导。后台不应附带通用默认密码。

## 2. 拟定本机布局

| 路径 | 用途 | 管理方式 |
| --- | --- | --- |
| `/usr/local/bin/filepanel` | 主程序 | 安装与受控更新维护 |
| `/etc/filepanel/` | 实例配置与必要凭据 | 限制读取权限 |
| `/var/lib/filepanel/` | SQLite、正式文件、素材和任务状态 | 专用服务用户拥有 |
| `/var/cache/filepanel/` | 临时传输与更新暂存 | 限额、定期清理、启动对账 |
| `/var/log/filepanel/` | 应用日志候选路径 | Alpine使用受限日志与轮转；Debian可用journald，均限制保留量 |
| OpenRC 服务脚本 / systemd 单元 | 按实际平台启动、停止、自启与受控恢复 | 记录安装清单，不要求Alpine安装systemd |

正式文件、素材与数据库不能放在公开静态目录中。大文件传输使用流式读写，临时文件可按配置放在有足够空间的数据盘；安装器不接管已有服务、任意挂载目录和整机防火墙。

两类系统共用业务与维护契约，仅适配必要的服务管理和系统命令。脚本不默认存在 Bash、GNU 工具或 journald；发布二进制优先无 CGO 外部运行库依赖，在 Alpine 与 Debian 分别实际运行，新增原生库时核验 musl/glibc 兼容性。不同系统的安装、重启、日志保留、更新回滚与卸载均需实际 smoke，不为此增加通用发行版插件框架。

主服务以专用用户运行。低端口绑定、二进制替换和服务重启的权限方案需在实现前确定，倾向采用最小权限服务配置与固定操作范围的维护机制，不能为了网页更新让整个面板长期以 root 运行或执行任意 shell。

## 3. 访问地址与 HTTPS

| 环境 | 可用入口 | HTTPS 处理 |
| --- | --- | --- |
| 公网直连且挑战端口可达 | IP 与端口；绑定后使用域名 | 集成 ACME，申请成功后启用 TLS 并自动续期 |
| 已有公网反向代理 | 既有代理域名 | 代理终止 TLS，面板使用内部监听与可信代理配置 |
| NAT 且有映射端口 | 公网 IP:映射端口，或域名:端口 | 依实际映射与证书条件处理，不能仅靠 DNS 获得标准 443 入口 |
| NAT 且要求无端口域名 | 外部公网反代或管理员提供的 Tunnel | 生成指导与配置，验证后再标记可用 |
| 无入站数据路径 | 尚无公开文件入口 | 标记阻塞原因，不宣称节点可下载 |

管理员填入域名后，分步检查 DNS、预期入口、端口冲突和证书申请条件。DNS 配置以完整域名为事实，主机记录只是根据托管区的建议，不应盲目把所有域名都拆成第一个标签。HTTP-01 与 TLS-ALPN-01 的可用条件不同，不能把“同时开放 80 和 443”当成所有证书流程的绝对条件；具体首版挑战方式在实现时确定。

证书只有实际签发并验证部署成功后才显示已启用。域名切换先验证新入口再更新对外地址，保留可恢复的旧管理入口与配置；续期失败提前提醒，不把一次 DNS 查询成功当作 HTTPS 正常。面板不能替用户在无授权的第三方 DNS 账号中添加记录。

已有 Nginx/Caddy 占用端口时，不自动覆盖其配置。教程可生成配置和明确的部署步骤；第三方 Tunnel 的传输限制、支持范围与适用条款需在具体实现时核查，不能笼统承诺适用于所有大文件分发。

## 4. 可选节点接入

管理员在数据页生成短期一次性入网命令。节点安装器下载对应架构的发布物，创建专用实例，使用票据连接主面板；面板确认注册后颁发节点独立凭据，票据失效。命令及日志不应长期暴露真实凭证，撤销节点后旧凭据不能继续读取文件。

节点默认只启用下载能力可作为首版建议，管理员可以开启存储。入网后分别检测控制连接、可用空间、数据端点与公开下载地址；公网 IP 可自动探测，但映射端口与外部反代路径不能可靠推断时必须由用户补充。仅能主动连接面板的 NAT 节点，不能因此获得未实现的反向传输能力。

控制与数据连接应使用经过验证的 TLS 或受支持的安全传输，不能默认跳过证书校验。节点域名与主域名独立配置，修改出口地址不改变主面板的稳定分享路径。

## 5. 更新与回滚

网页更新目标包括主面板和节点，执行流程为检查兼容性与空间、获取可信版本清单、下载并校验、备份程序与数据库、进入维护阶段、原子替换、重启、健康检查。运行中的传输先等待到有界时间或明确通知中断，避免更新无限等待。

健康检查失败时恢复旧程序与配置；数据库迁移必须事先说明可逆性，不能假定新数据库可以直接用旧程序打开。需要恢复数据库快照的回滚必须在维护状态完成，避免丢弃升级后新写入的数据。主节点协议不兼容时展示升级顺序并禁止带病更新。

发布仓库、版本元数据格式、签名方案、维护组件权限和兼容窗口尚未确定。在这些环节完成前，不能在 README 放置看似有效的安装 URL 或声称支持自动更新。

## 6. 备份与迁移

个性化导出只恢复全站品牌、样式和引用素材，不是文件备份。完整迁移还需要一致性的 SQLite 备份、正式文件、资源内容素材、实例配置和必要密钥；远端节点的数据需在对应节点另行备份，备份主面板不会自动包含它们。

数据库运行中应使用 SQLite 支持的一致性备份方式，不能只复制可能仍在写入的主数据库文件而忽略 WAL。文件备份需与元数据快照协调；恢复后检查文件大小/哈希、存储位置、节点认证、公开状态和真实下载。迁移期间不自动打开所有资源的主页展示。

备份属于运行可靠性的必要设计，但首版是否提供网页全量备份功能仍待决定。未实现前需要给出经过验证的维护流程，不能把“导出个性化”描述成一键整站迁移。

## 7. 卸载

拟提供 `filepanel uninstall` 保留数据，以及 `filepanel uninstall --purge` 彻底删除两种语义。原聊天提出的彻底卸载需一次明确确认，界面列出本实例的数据根目录、文件范围和不可恢复后果，再要求输入确认词。

实际清理严格依安装清单，停止服务后删除本实例拥有的程序、服务、配置、数据库、文件、素材、日志和缓存。递归操作前解析绝对路径并拒绝根目录、共享目录和链接逃逸；自定义路径必须确认所有权，不能直接清空整个用户数据盘。卸载本机面板不等于删除其他服务器上的节点文件，远端实例需独立处理并在结果中说明。

### 7.1 对远端节点的影响

面板机执行保留数据卸载或彻底卸载时，均不向远端节点发送卸载或删除文件命令。节点程序、正式文件、本地配置和用量继续保留，主面板离线后按[节点失联规则](02-架构与数据设计.md#51-主面板失联与卸载后的节点行为)停止新下载，已开始的响应受有效会话租约、撤销状态和本地流量保护约束。远端节点必须在对应机器上独立卸载；仅本机清理成功时，结果应写成“主面板本机已卸载，远端节点未清理”。

彻底卸载还会删除主面板的文件索引、分享配置和节点凭据。原主面板的分享入口失效，重新安装不会自动找回远端节点与文件管理关系；远端文件存在不等于元数据和授权关系仍可恢复。保留数据卸载可用于后续恢复，但重新安装后仍须验证原数据库、凭据与节点状态，不能仅凭服务启动就宣称已恢复。

### 7.2 确认前的节点清单与提示

卸载命令应在清理数据库前读取本地节点与文件记录，在同一次确认中列出远端节点的 IP/端口、备注、最后在线时间、关联文件数量和已记录文件总大小。离线节点与过期统计必须明确标记，数量和大小只是面板最后已知记录，不能冒充实时远端扫描；即使远端不可达，也不能显示成“没有文件”。

提示必须说明：本操作只卸载主面板本机，远端程序和文件保留，分享入口将不可用，彻底卸载后重装不会自动恢复管理关系；需要清理远端时应另行到各节点处理。保留原有一次确认，不逐台增加确认，也不自动扩展为全系统卸载。元数据损坏或无法读取时显示“远端节点清单未知”，仍明确远端不会被清理，不能以空清单报告整个系统已删除。

## 8. 运维反馈

错误日志记录时间、实例、任务 ID、错误类别与可恢复信息，遮蔽密码、入网票据和下载凭证。日志、缓存、失败任务与临时文件有明确保留上限，空间不足不能导致无限错误日志继续塞盘。

数据页展示用量最后更新时间、策略状态与节点失联信息。状态未知时保留最后一次数据并标记过期，不能当作零流量或健康；节点失联期间仍执行本地配额，重新上线后通过累计值补报。
