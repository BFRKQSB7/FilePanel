# 本地签名更新与一致性备份

安装包通过项目 GitHub Releases 在线分发，也可离线交付；网页更新仍采用管理员预置、网页确认的流程。面板和节点各自安装、各自备份、逐台更新。个性化配置包不等于整站备份，面板备份不包含远端节点的正式文件。

## 发布物与信任

开发机执行 `python scripts/build-release.py --fixture` 可生成两个正常版本与一个启动失败版本的隔离验收 fixture。开发签名私钥仅留在输出根目录，绝不进入安装 ZIP；这套密钥只供本地验收，不作为公共生产发布身份。正式维护者应离线生成并保护自己的 Ed25519 私钥，执行：

```sh
python scripts/build-release.py --key /private/offline-signing.key --version 0.1.0 --sequence 1
```

私钥文件是 64 字节 Ed25519 私钥的标准 base64 编码。发布清单采用 Ed25519 签名，固定产品、三段数字版本、严格递增序号、源码归档 SHA256、schema/协议范围、Linux 架构、产物大小与 SHA256。安装前通过独立可信渠道核对引导程序与清单摘要，并分发公钥；同一个陌生站点提供的文件、hash 与公钥不能建立独立信任。每个产物的 `version` 命令显示精确构建信息，`source.zip` 保存构建输入；`source.json` 说明 Git 基线与是否有未提交改动。

安装时在原安装参数后附加 `--update-key "$(cat /root/release/trusted.pub)"`，公钥随 root 控制的安装配置固定。传入签名清单时安装器会在创建服务账号前验证签名。未分发更新公钥的旧安装继续运行，网页明确显示维护代理不可用；不得通过编辑安装清单或放宽文件权限自行接入未知公钥。

## 网页更新

把下一版本对应架构的二进制和签名 `release.json` 放入 root 控制的目录。管理员在服务器上预置更新，网页不能输入 URL、shell、路径或任意程序：

```sh
sudo /opt/filepanel-main/filepanel maintain --instance main \
  --action stage-update --release /root/release-next/release.json
```

安装器自动管理 `filepanel-main-update` 维护代理。它只在本机 Unix socket 接受“读状态”和“应用预置更新”两个动作，socket 仅 root 与该实例专用组可访问；网页服务本身仍以非 root 用户运行。旧式独立运行 `serve` 不会自行获得系统维护权限。管理员可以用 `filepanel update-agent --instance main` 在前台诊断代理，不能同时启动两个代理。

设置页点击“检查预置更新”，确认版本后点击“更新本机面板”。节点卡片提供“检查节点预置更新”“更新此节点”；先在对应节点服务器预置其签名包，再逐台触发。离线、身份不符或协议/schema 不兼容的节点立即拒绝，不会偷偷排队执行。

更新先检查完整空间峰值并校验签名、版本、真实 ELF 架构和静态运行库要求，再设置持久维护屏障，停止服务并取得独占锁。一致性快照完成后原子替换程序，新程序在屏障内迁移并通过真实 HTTP 健康、版本、文件/素材哈希及元数据读取校验，才提交并恢复访问。活动下载有受限停止期限；后台移动与上传由原有持久状态恢复，维护不会无限等待读租约。

失败会恢复原程序和一致性快照，systemd 回退只重置本实例的失败启动计数；OpenRC 同样只处理本实例。断电或代理重启会根据 root 私有日志幂等恢复。已经提交、解除屏障的更新不会自动恢复旧快照，因为这会丢弃新写入。必要时用独立、可信的引导程序运行：

```sh
sudo /root/release/filepanel-linux-amd64 maintain --instance main --action recover-update
```

更新前的快照 `config/update-snapshot`、原程序 `config/previous-binary` 和失败预置包会保留。管理员核对当前实例健康、另存所需回退资料后，才能清理这几个**本实例**历史路径以进行下一次维护；有未完成日志时先恢复，不能直接删除现场。恢复切换产生的冗余旧数据目录在持久提交后清理，快照仍保留。不要把备份放进公开文件目录。

## 已安装实例的备份与恢复

```sh
sudo /opt/filepanel-main/filepanel maintain --instance main \
  --action backup --backup-path /root/backups/site-before-update
sudo /opt/filepanel-main/filepanel backup verify --path /root/backups/site-before-update
sudo /opt/filepanel-main/filepanel maintain --instance main \
  --action restore --backup-path /root/backups/site-before-update
```

备份目标必须不存在，父目录必须是 root 控制的安全目录，并位于数据目录外。备份与更新共用停写屏障和数据目录锁，SQLite 使用 `VACUUM INTO` 保留已提交 WAL 数据，同时保存本机对象、资源图片和站点素材。备份采用私有目录格式：`snapshot.json` 给出格式、schema、角色、本机文件大小/hash和未包含的远端文件数量；SQLite 保留完整远端文件/节点关联清单。密钥、账号哈希与 TLS 配置也在 SQLite 内，备份必须限制权限并加密离线保管，不能公开分发。

恢复前逐文件检查路径、链接、大小、SHA256、SQLite 完整性/外键、角色、schema 和本机对象/素材引用。文件先复制到同一文件系统的隔离目录，再停写切换；失败保留当前实例。原地恢复只接受同一面板/节点身份；恢复会回到备份时的文件名、分享授权、账号与密钥状态，**因此必须明确选择备份时点**。节点租约不会跨重启沿用，恢复后需要重新完成节点控制/TLS/身份检查。

## 新隔离实例恢复

无需安装服务也可使用相同备份格式；运行服务时先停止原进程，不能绕过独占锁复制活跃 DB：

```sh
filepanel backup create --data-dir /private/site --path /private/site-backup
filepanel backup verify --path /private/site-backup
filepanel backup restore --path /private/site-backup --data-dir /private/restored-site
filepanel serve --data-dir /private/restored-site --listen 127.0.0.1:8080
```

恢复目标必须是不存在的新目录。节点备份恢复后使用 `node serve`，不能当作面板启动。隔离验证实际下载、公开状态与节点身份后，再安排入口切换；不要同时运行具有相同身份的旧、新面板。此命令不会自动接管已有安装清单、旧节点或服务账号。

## 空间和验收边界

默认预留为 **16MiB 与实际磁盘容量 5% 的较大值**，保留在途预算；上传、图片/配置/证书写入共享预算，维护在停写后进行完整峰值预检并逐块检查空间。不能用零预留绕过 1GB 小盘保护。备份/更新可能需要同时容纳原数据、快照和隔离恢复副本，空间不够时先拒绝，当前程序和数据继续保留。

首版目标为套餐 1 vCPU、整机/容器 128MB、磁盘 1GB；是否通过以对应发布产物的真实验收报告为准。已有 swap、整机限额、RSS/cgroup 峰值、实际 NAT、TLS 信任方式和跨机路径分别记录。Alpine/OpenRC、Debian/systemd 与 Ubuntu 24.04 LTS/systemd 的结果不能互相替代，交叉编译不能当作运行通过。64MB 仅为可选探底，不承诺支持。
